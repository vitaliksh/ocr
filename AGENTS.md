# AGENTS.md

Правила для любого AI-агента (Codex, Claude и др.) в этом репозитории.
Подробности продукта — `docs/HANDOFF.md`, `docs/ARCHITECTURE.md`,
`docs/RIVHIT_IMPORT_SPEC.md`. Здесь только то, что нельзя нарушать.

## Границы задачи

- Не добавляй функциональность вне задачи. «Заодно сделал ещё X» — это долг.
- Минимальный дифф. Не меняй, не упрощай и не «чисти» работающий код вне цели
  задачи. Новый функционал — через новые параметры с дефолтами, обёртки или
  композицию; существующие интерфейсы не ломай.
- Рефакторинг (форматирование, вынос функций) — только как отдельная задача и
  отдельный коммит, без изменения поведения. Не смешивай с фичами и фиксами.
- UI на иврите. Не переводи и не переформулируй тексты интерфейса без явной
  просьбы.

## Продуктовые границы (нарушать нельзя)

- Локально-первое приложение. Данные клиентов, декларации, черновики, исходные
  изображения, PDF, TXT, экспорты и история остаются в выбранной локальной
  папке. В облако (Worker, R2, Durable Objects, GitHub) они не попадают. R2
  держит Telegram-изображение только до ACK браузера.
- Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `GEMINI_API_KEY`,
  `ALLOWED_TELEGRAM_USER_ID`) существуют только как Worker secrets. Не
  печатать, не коммитить, не класть в browser storage, не логировать
  сессии и гранты.
- Gemini не придумывает исходные факты, коды Form 6111 и коды Rivhit. Pass 2 не
  меняет дату, поставщика, ID, референсы, номер аллокации, суммы и валюту.
  Pass 2 получает только текст из истории, без изображений.
- Экспорт TXT — по `docs/RIVHIT_IMPORT_SPEC.md`: CP1255, CRLF, без заголовка,
  ровно 186 полей. Перед экспортом валидируются все активные строки.
  Любое изменение экспортёра проверяй на реальном шаблоне и импортом в Rivhit.
- Закрытая декларация не открывается молча. История добавляется один раз по
  `declarationId`.
- Python-приложение и exploratory package flow удалены намеренно — не
  возвращать.
- Приложение — помощник бухгалтера, не налоговая консультация.

## Приватность и тестовые данные

- `examples/`, `pdf examples/`, `tmp/`, `processed_documents/`, `example.JPG` —
  реальные или похожие на реальные документы. Не коммить новые, не пересылай
  в сторонние сервисы и не вставляй их содержимое в issues/PR.
- Для тестов используй синтетические данные.

## Работа с кодом

- Перед правкой читай окружающий код. Стиль, имена и плотность комментариев —
  как вокруг.
- Новый код — без цепочек `const a = ..., b = ...` на десятки элементов и без
  строк длиннее ~120 символов.
- Никаких новых глобальных переменных. Состояние — через существующие
  объекты/модули или параметры.
- Баг: сначала воспроизведи тестом или логом, потом чини. Не повторяй тот же
  фикс дважды; после неудачи разбери причину по ошибке.
- Утверждение «X невозможно/недоступно» без минимального воспроизводимого
  эксперимента — гипотеза, так и помечай.
- Всё, что зависит от внешнего мира (Telegram/Gemini/Cloudflare API, версии,
  браузерные API), проверяй по актуальной официальной документации.

## Definition of Done

- У задачи есть проверяемый критерий готовности («экспорт 30 строк, 186
  колонок, Rivhit импортирует»), а не «реализовано и собирается».
- Тесты и документация обновляются в том же коммите, что и код. README,
  `docs/HANDOFF.md` и ожидаемое число тестов не должны расходиться с
  реальностью.
- Перед коммитом зелёные: `npm test` и `npm run check` в `telegram-web/`;
  `npm test` и `npm run check` в `cloudflare-worker/` (если трогал Worker).
- Фронтенд-изменение: проверь вручную в Edge/Chrome на опубликованной странице
  (Ctrl+F5, сверь маркеры версий). Worker-изменение: `npx wrangler deploy`,
  версию — в `cloudflare-worker/DEPLOYMENT.md`.
- Не можешь проверить — скажи об этом прямо.

## Git

- Одна задача — один коммит, сообщение на английском и по существу.
- Деструктивные операции (force push, удаление данных, reset) — только после
  подтверждения владельца. Не трогай чужие несохранённые изменения.
- Push в `main` публикует GitHub Pages: проверенное, не промежуточное.
